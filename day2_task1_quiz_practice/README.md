# 오전 과제: 복습 퀴즈 앱 만들기 (뼈대)

2일차 11:00~ | [전체 일정으로](../README.md) | 완성: [day2_task1_quiz_answer](../day2_task1_quiz_answer)

버튼을 누르면 인터넷에서 문제를 받아 와 하나를 보여 주는 앱입니다. 화면은 만들어져 있습니다.

File > Open으로 이 폴더를 열고 Run 하면 복습 퀴즈 화면이 뜹니다. 아래 [1]부터 차례로 채우고, 채울 때마다 Run 합니다. 파일 안에 `[1] 여기를 채웁니다`처럼 자리가 표시되어 있습니다.

전체 흐름은 이렇습니다.

```
버튼 누름 → load() → fetchQuizzes() 가 인터넷에서 받아 옴 → 상태(_state)를 바꿈 → 화면이 바뀜
```

## [1] 인터넷에서 문제 목록 받아 오기

**하는 일**: `fetchQuizzes()`는 인터넷 주소에서 글자를 받아 와 문제 목록으로 바꿔 돌려주는 함수입니다. 인터넷은 오래 걸릴 수 있어서 `withContext(Dispatchers.IO) { }` 안(IO 스레드)에서 합니다. 이 부분은 이미 적혀 있습니다.

**채울 곳**: `practice/QuizApp.kt`의 `fetchQuizzes()` 중괄호 안. 지금 있는 `emptyList()`(빈 목록)를 지우고 두 줄을 씁니다.

```kotlin
suspend fun fetchQuizzes(): List<Quiz> = withContext(Dispatchers.IO) {
    val text = ______________     // ① 주소의 글자를 모두 읽어 text 에 넣음
    ______________                // ② text 를 문제 목록으로 바꿈
}
```

**힌트**
- ① 주소는 `QUIZ_URL`입니다. `URL(주소)`로 주소를 만들고, 거기에 `.readText()`를 붙이면 글자를 모두 읽어 옵니다.
- ② `QuizScreen.kt`에 글자를 문제 목록으로 바꿔 주는 함수 `parseQuizzes`가 있습니다.
- `withContext { }`는 마지막 줄의 값을 돌려줍니다. 그래서 ②에는 `return`을 쓰지 않습니다.

**확인**: Run 해도 화면은 그대로입니다. 받아 오는 함수만 만들었고, 아직 버튼이 이 함수를 부르지 않기 때문입니다. 빨간 줄 없이 Run 되면 됩니다.

## [2] 버튼을 누르면 받아 와서 보여 주기

**하는 일**: 버튼을 누르면 `load()`가 불립니다. 여기서 [1]의 함수를 불러 문제를 받고, 화면 상태(`_state`)에 넣습니다. 상태를 바꾸면 화면이 알아서 다시 그려집니다.

**채울 곳**: 같은 파일의 `load()` 안. 지금 있는 안내 줄(`아직 [2] 를 안 채웠어요`)을 지우고 아래 모양으로 씁니다.

```kotlin
fun load() {
    _state.value = ______________              // ① 화면을 "받아 오는 중"으로
    viewModelScope.launch {                    // 코루틴 시작 (인터넷을 기다리는 동안 화면이 안 멈춤)
        val quizzes = ______________           // ② [1]의 함수로 문제 목록을 받음
        _state.value = ______________          // ③ 그중 하나를 골라 화면에 보여 줌
    }
}
```

**힌트**
- 화면 상태의 종류는 `QuizScreen.kt`의 `QuizState`에 있습니다: `Ready`(처음), `Loading`(받아 오는 중), `Success(문제)`(받아 옴), `Error(글자)`(못 받아 옴).
- ①은 이 가운데 "받아 오는 중"입니다. ③은 "받아 옴"이고, 괄호 안에 문제 하나를 넣습니다.
- 목록에서 아무거나 하나를 고르는 함수는 `random()`입니다. 예: `목록.random()`
- `viewModelScope`는 ViewModel 안에서 코루틴을 시작하는 곳입니다. 화면을 완전히 닫으면 이 코루틴도 같이 멈춥니다.

**확인**: "하나 받아 오기"를 누르면 잠깐 "받아 오는 중"이 보이고 문제가 뜹니다. "정답 보기"를 누르면 답이 보입니다.

## [3] 인터넷이 안 될 때 안내하기

**하는 일**: 인터넷이 끊겨 있으면 `fetchQuizzes()`에서 예외가 나고 앱이 꺼집니다. 예외를 잡아서 앱이 꺼지는 대신 안내 글자를 보여 줍니다.

**채울 곳**: [2]에서 `launch { }` 안에 쓴 두 줄(②, ③)을 `try { }`로 감싸고, 뒤에 `catch`를 붙입니다. 파일 안의 `[3]` 주석은 이 자리를 가리킵니다.

```kotlin
    viewModelScope.launch {
        try {
            // [2]에서 쓴 두 줄
        } catch (e: Exception) {
            ______________                     // 실패했을 때 보여 줄 상태
        }
    }
```

**힌트**: `QuizState` 가운데 "못 받아 옴"을 `_state.value`에 넣습니다. 괄호 안에는 보여 줄 글자를 넣습니다. 예: "받아 오지 못했습니다. 인터넷 연결을 확인해 주세요"

**확인**: 에뮬레이터의 Wi-Fi와 모바일 데이터를 끄고 누르면 앱이 꺼지지 않고 안내 글자가 뜹니다. 확인한 뒤 다시 켭니다.

## [4] 멈추는 화면 고치기

**하는 일**: 메인 스레드에서 3초 걸리는 일을 하면 그동안 화면이 멈춥니다. 오래 걸리는 일만 워커 스레드로 보내서 화면이 멈추지 않게 합니다.

에뮬레이터의 앱 목록에서 "멈춤 고치기" 아이콘을 엽니다. "3초 걸리는 일"을 누르면 3초 동안 "눌러 보기"의 숫자가 안 오릅니다.

**채울 곳**: `practice/FreezeFix.kt`에서 `[4] 여기를 고칩니다` 아래의 `result = slowWork()` 한 줄을 아래 모양으로 바꿉니다.

```kotlin
result = "일하는 중"                     // 먼저 글자를 바꿔 둠
scope.launch {                           // 코루틴 시작
    result = ______________              // 3초 걸리는 slowWork() 를 워커 스레드에서
}
```

**힌트**
- `scope`는 이 화면에서 코루틴을 시작하는 곳입니다. 파일에 이미 만들어져 있습니다.
- 워커 스레드로 보내는 방법은 [1]과 같은 `withContext(...) { }`입니다. 계산처럼 CPU를 쓰는 일은 `Dispatchers.IO` 대신 `Dispatchers.Default`를 씁니다.

**확인**: "3초 걸리는 일"을 누른 뒤 "눌러 보기"를 누르면 숫자가 바로 오릅니다. 3초 뒤에 "끝났습니다"가 뜹니다.
